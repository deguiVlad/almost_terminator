# Проверка решений

Как оцениваются решения и в каком виде их сдавать. Задачи и варианты описаны в [TASKS.md](TASKS.md), интерфейсы
робота — в [INTERFACES.md](INTERFACES.md) (краткая справка — в
[шпаргалке](nssr_hackathon_interfaces_cheatsheet_RU.md)).

## Что проверяется

Решения проверяют организаторы на случайных раскладках, которые заранее неизвестны. Решение должно стабильно
работать на любой раскладке, а не на нескольких удачных сидах.

Проверяются все задачи для всех команд: сортировка `sort2` и `sort3` на пуле вашей команды, дополнительная `sort2`
на пуле 6 и все четыре варианта
пробирок (`easy`, `standard`, `color`, `lying`). Задачу, которую команда не решала, решение может пропустить, сразу
опубликовав сигнал завершения `/sim/task/done`: за неё будет 0 баллов.

Оцениваются только финальные задачи. Подготовительные блоки трека (кинематика рук; кисти, голова и корпус;
детекция) отдельно не проверяются: без них финальные задачи не решить.

Финальные задачи решаются последовательно. Баллы за пробирки и за дополнительную `sort2` на пуле 6 засчитываются,
только если решение справляется с сортировкой на своём пуле: суммарный итог по `sort2` и `sort3` на пуле команды
должен быть положительным. Сортировка не обязана быть идеальной,
но без неё пробирки не учитываются.

## Баллы

Каждый объект и каждая пробирка весят одинаково, 10 баллов.

Сортировка:

| Итог по объекту | Баллы |
|---|---|
| в сортировочном ящике своей категории | +10 |
| в ящике чужой категории | -10 |
| взят и оставлен вне ящиков | -10 |
| упал на пол | -10 |
| не тронут | 0 |

Пробирки:

| Итог по пробирке | Баллы |
|---|---|
| стоит в правильном штативе в шкафу | +10 |
| стоит в чужом штативе | -10 |
| взята и оставлена не в штативе: на столе, в шкафу, лежит или наклонена в гнезде | -10 |
| упала на пол | -10 |
| не тронута | 0 |

"Стоит" значит, что дно пробирки в гнезде и отклонение от вертикали меньше 20 градусов, см. [TASKS.md](TASKS.md).
Баллы складываются по всем раскладкам и всем задачам. Каждый решённый вариант пробирок добавляет баллы, отдельных
бонусов за пробирки нет.

Максимум на одной раскладке:

| Задача | Объектов | Максимум |
|---|---|---|
| `sort2` | 6 | 60 |
| `sort2` на пуле 6, дополнительно | 6 | 60 |
| `sort3` | 9 | 90 |
| пробирки `easy` | 4 | 40 |
| пробирки `standard` | 9 | 90 |
| пробирки `color` | 6 | 60 |
| пробирки `lying` | 6 | 60 |

Дополнительная `sort2` на пуле 6 считается как обычная сортировка, по 10 баллов за объект, сверх основных задач.
Пул 6 состоит из других объектов, чем пул команды, и решение должно распознавать их в дополнение к своим
(см. раздел "Варианты" в [TASKS.md](TASKS.md)).

## Время

На каждую раскладку есть лимит времени симуляции: 45 секунд на объект сортировки и 60 секунд на пробирку.

| Задача | Лимит, секунды симуляции |
|---|---|
| `sort2`, 6 объектов, в том числе на пуле 6 | 270 |
| `sort3`, 9 объектов | 405 |
| пробирки `easy`, 4 штуки | 240 |
| пробирки `standard`, 9 штук | 540 |
| пробирки `color`, 6 штук | 360 |
| пробирки `lying`, 6 штук | 360 |

Когда решение закончило раскладку, оно публикует `std_msgs/Empty` в `/sim/task/done`. После этого или по
истечении лимита задача заканчивается и считаются баллы. Без сигнала завершения временем решения считается весь
лимит.

При равных баллах выше то решение, которое:

1. быстрее справляется с задачами по времени симуляции;
2. быстрее работает по реальному времени;
3. меньше нагружает компьютер: процессор, оперативную и видеопамять;
4. проще и компактнее по коду.

Пробирки и штативы у всех команд одинаковые, меняется только раскладка. Поэтому при близких баллах по пробиркам всё
решают время работы и код решения. Решения сравниваются между собой. Совпадающий код, если это не шаблон
`hello_world` и не общедоступные библиотеки, считается списанным, такие решения аннулируются.

## Формат решения

Решение лежит в репозитории вашей команды `nssr-sol-team-NNN`, ветка `main`:

```
nssr-sol-team-NNN/
  src/              пакеты ROS 2 (Python или C++), собираются colcon
  apt.txt           apt-пакеты, по одному в строке (необязательно)
  requirements.txt  pip-пакеты, лучше с версиями (необязательно)
  setup.sh          остальная установка: веса моделей, сборка из исходников (необязательно)
  run.sh            запуск решения
  README.md         описание решения по каждой задаче (обязательно)
```

Отчёт о решении, обязательно:

- `README.md` в корне репозитория: как устроено решение по каждой задаче (детекция, положение объектов по глубине,
  захват, раскладка), какие модели и библиотеки используются, как запускать.
- Скринкасты: по одному на каждую задачу и вариант, которые решает команда. На записи окно симулятора от старта
  задачи до сигнала завершения и терминал со строкой `layout seed`. Видео прикладываются к релизу репозитория
  команды (Releases), а не в git: mp4, до 2 ГБ на файл.

README и скринкасты сверяются с работой решения на итоговой проверке. Если поведение решения заметно расходится с
описанием и записями, решение по этой задаче не засчитывается до объяснения.

Решение ставится в отдельный контейнер из образа симулятора (`hackathon/docker/Dockerfile`), копия репозитория
решения лежит в `/solution`. Установка, по порядку:

```bash
cd /solution
apt-get update && xargs -a apt.txt apt-get install -y --no-install-recommends    # если есть apt.txt
/usr/bin/python3 -m pip install -r requirements.txt                              # если есть requirements.txt
bash setup.sh                                                                    # если есть setup.sh
source /opt/ros/humble/setup.bash && colcon build
```

Запуск:

```bash
cd /solution && source install/setup.bash && bash run.sh
```

Требования:

- Один и тот же `run.sh` работает для всех задач и вариантов: решение само узнаёт задачу из `/sim/task`, само
  находит объекты камерами и в конце публикует `/sim/task/done`.
- С симулятором решение связано только через ROS 2. `ROS_DOMAIN_ID` и профиль DDS уже заданы в контейнере, в
  `run.sh` их менять не нужно. Файлов репозитория симулятора в контейнере решения нет.
- Видеокарта решению доступна. PyTorch и другие библиотеки ставьте через `requirements.txt`.
- Интернет есть только на этапе установки. Всё, что решение скачивает (веса моделей и т.п.), скачивайте в
  `setup.sh`, а не в `run.sh`. Файлы больше 100 МБ GitHub в репозиторий не примет, такие веса тоже скачивайте в
  `setup.sh`.
- Решение не меняет симулятор и определяет положение объектов только по данным датчиков робота, см. раздел
  "Правила решения" в [TASKS.md](TASKS.md).

Проверить формат у себя: запустите симулятор с задачей, затем во втором терминале из корня репозитория
симулятора:

```bash
bash hackathon/tools/solution.sh ~/nssr-sol-team-NNN
```

Скрипт делает ровно эту установку и запуск в чистом контейнере. Если решение отработало так у вас, его можно
сдавать.

## Сроки

В момент дедлайна доступ к репозиториям решений переводится в режим только для чтения. Проверяется последний
коммит в `main` до дедлайна. Дата дедлайна указана в регламенте хакатона.
