# 📋 Шпаргалка хакатона nssr-sim: задачи, интерфейсы, баллы

Всё самое нужное на одном листе. Подробные версии разделов — в [TASKS.md](TASKS.md), [INTERFACES.md](INTERFACES.md) и [SCORING.md](SCORING.md).

Симулятор `nssr-sim` — контейнер с ROS 2 Humble + Isaac Sim, робот TienKung 2.0 Pro (не ходит: стоит у стола, ноги закреплены). `ROS_DOMAIN_ID=146`, профиль DDS `hackathon/docker/fastdds_hack.xml`. Обёртка `bash hackathon/tools/ros.sh <команда>` сама источникит ROS и подставляет домен; без неё перед любой `ros2`-командой: `source /opt/ros/humble/setup.bash && export ROS_DOMAIN_ID=146`.

## 1. Быстрый старт

```bash
bash hackathon/tools/task.sh list                     # задачи, пулы объектов, варианты пробирок
bash hackathon/tools/task.sh sort3 --pool 2           # сортировка: 3 категории из пула 2, 3 ящика
bash hackathon/tools/task.sh sort2 --pool 4 --seed 7  # сортировка: 2 категории, 2 ящика, раскладка по сиду 7
bash hackathon/tools/task.sh tubes                    # пробирки, вариант standard
bash hackathon/tools/task.sh tubes --variant lying    # пробирки лежат на столе
bash hackathon/tools/task.sh info                     # что куда раскладывать
bash hackathon/tools/task.sh check                    # сколько уже сделано (ответ в /sim/task/result)
bash hackathon/tools/objects.sh randomize 5           # новая раскладка с сидом 5 (без перезапуска)
```

Опции запуска: `--seed S` (зафиксировать раскладку), `--cams head` (одна камера, быстрее), `--headless` (без окна Isaac, камеры работают), `--media` (качество картинки, медленнее); всё после `--` уходит в `run_sim.sh`. То же — переменными `HACK_TASK`, `HACK_POOL`, `HACK_TUBES`, `HACK_SEED`, `HACK_CAMS`. Все параметры: `run_sim.sh --help`.

Пример узла (читает суставы, камеру, задачу; двигает головой и кистью): `hackathon/ros2/hello_world`. Проверка interfaces: `bash hackathon/tools/ros.sh python3 /nssr_sim/hackathon/tools/check_interfaces.py`.

## 2. Задачи

Три подготовительных блока (зачёт/незачёт, отдельных баллов нет): обратная кинематика рук; кисти, голова и корпус; детекция по камерам головы и торса с глубиной. Две финальные задачи решаются последовательно: сначала сортировка, потом пробирки.

**Пулы объектов:** `пул = (номер команды - 1) mod 5 + 1` (команда 7 → пул 2). Пулы не пересекаются; остальные — для отладки.

- **`sort3`** — 9 объектов, 3 категории по 3 шт, 3 ящика; **`sort2`** — 6 объектов, первые две категории пула, 2 ящика. В каждом ящике ровно одна категория. Ящики: `tray_left` красный, `tray_right` синий, `tray_center` зелёный; правило — в `/sim/task` (`categories`), имена и категории объектов — в `/sim/objects/names`. Позы объектов не публикуются — только камеры.
- **`tubes`** (звёздочка; баллы только если сортировка на своём пуле решена). Слева вытяжной шкаф со штативами; взять пробирку, повернуть корпус влево (ноги на месте), поставить вертикально в штатив шкафа, вернуться. Пробирки конические Falcon: 50 мл ⌀29×114 мм, 15 мл ⌀17×120 мм, цветные крышки; гнёзда квадратные: 36 / 22.5 мм. Считается поставленной, если дно в гнезде и отклонение от вертикали < 20°. Оптимизация слабых видеокарт: `HACK_SASH=0`, `HACK_HOOD_LIGHT=0` (на задачу не влияет).

| Вариант | Что на столе | Правило |
|---|---|---|
| `easy` | 4 пробирки 50 мл в штативе | в любое гнездо штатива в шкафу (`any_slot`) |
| `standard` | 4×50 мл + 5×15 мл в двух штативах | в штатив своего размера (`by_type`) |
| `color` | 6×50 мл с красными и синими крышками | по цвету крышки (`by_cap_color`) |
| `lying` | 3×50 мл и 3×15 мл лежат | вертикально, штатив своего размера |

**Раскладка и сиды.** Каждый запуск раскладывает объекты случайно; сид печатается в логе (`layout seed 12345 …`), повторить — `--seed 12345`. Для сортировки сид задаёт позы объектов на столе, для пробирок — занятые гнёзда и цвета крышек. На итоговой проверке организаторы берут свои сиды из всего диапазона целых чисел, решению они недоступны — подгонять решение под конкретные раскладки бесполезно.

**Правила решения.** Положение объектов определяйте только по датчикам робота (камеры + глубина, энкодеры, датчики силы, состояние кистей). Чтение сцены USD, геометрии/поз объектов, состояния физики, внутренних API Isaac и правки симулятора запрещены — **полученные в обход датчиков координаты аннулируют решение по задаче** (до дедлайна можно сдать исправленное). Разрешено читать `/sim/task` и `/sim/objects/names`. Топики `/sim/objects/set`, `/sim/objects/randomize`, `/sim/task/check` — отладочные, на итоговой проверке отключены, обращения к ним фиксируются.

## 3. Моторы и движение

Группы: `arm` — моторы 11–17 (левая) и 21–27 (правая), `head` — 1–3, `waist` — 31. Углы в рад, скорости в рад/с; оси: x вперёд, y влево, z вверх; базовое звено `pelvis`. Цели за пределами суставов обрезаются. `/leg/*` заморожены (ног в симуляции нет), наклон/высота базы (`/hric/robot/float_base_rpyz_cmd`) — только на реальном роботе. Для пробирок достаточно повернуть корпус на 1.57 рад.

| ID | Сустав | Пределы, рад |
|---|---|---|
| 1 / 2 / 3 | `head_roll` / `head_pitch` (плюс вниз) / `head_yaw` (плюс влево) | [-0.45, 0.45] / [-0.44, 0.44] / [-1.57, 1.57] |
| 31 | `body_yaw_joint`, поворот корпуса (плюс влево) | [-2.97, 3.14] |
| 11 / 21 | `shoulder_pitch_{l,r}` | [-2.97, 2.97] |
| 12 / 22 | `shoulder_roll_{l,r}` | левый [-0.26, 2.62], правый [-2.62, 0.26] |
| 13 / 23 | `shoulder_yaw_{l,r}` | [-2.97, 2.97] |
| 14 / 24 | `elbow_pitch_{l,r}` | [-2.62, 0.26] |
| 15 / 25 | `elbow_yaw_{l,r}` | [-2.97, 2.97] |
| 16 / 26 | `wrist_pitch_{l,r}` | [-0.79, 1.05] |
| 17 / 27 | `wrist_roll_{l,r}` | левый [-1.66, 1.31], правый [-1.31, 1.66] |

| Топик | Тип | Напр. | Примечание |
|---|---|---|---|
| `/{arm,head,waist}/cmd_pos` | `bodyctrl_msgs/CmdSetMotorPosition` | в | `name`: ID, `pos`: цель (рад), `spd`: рад/с (0 = предельная), `cur` не используется |
| `/{arm,head,waist}/cmd_vel` | `bodyctrl_msgs/CmdSetMotorSpeed` | в | рад/с; без новых команд 0.25 с мотор держит позицию |
| `/{arm,head,waist}/cmd_ctrl` | `bodyctrl_msgs/CmdMotorCtrl` | в | в симуляторе работает только `pos`; kp/kd/spd/tor не эмулируются |
| `/{arm,head,waist}/status` | `bodyctrl_msgs/MotorStatusMsg` | из, 20 Гц | `pos` и `speed` каждого мотора |
| `/joint_states` | `sensor_msgs/JointState` | из, 20 Гц | все суставы, включая пальцы |
| `/tf`, `/tf_static` | `tf2_msgs/TFMessage` | из, 10 Гц / стат. | дерево звеньев из URDF (`assets/robots/tiangong_pro/`), есть и в `/robot_description` |

⚠️ Скорость всех моторов рук/головы/корпуса ограничена **0.8 рад/с**, лимит действует и на итоговой проверке: `spd > 0.8` и `spd: 0` в `cmd_pos` и `cmd_ctrl` дают 0.8 рад/с, `cmd_vel` обрезается до [-0.8, 0.8]. Приводы — ПД-регуляторы: под весом руки недолёт до 15 % у плеча; для точного позиционирования замыкайте контур по `/joint_states`. Полный формат сообщений: `ros.sh ros2 interface show bodyctrl_msgs/msg/CmdSetMotorPosition`.

## 4. Кисти Inspire

По 6 приводов: `1` мизинец, `2` безымянный, `3` средний, `4` указательный, `5` сгиб большого, `6` поворот большого. `position`: 1.0 раскрыт, 0.0 сжат.

| Интерфейс | Тип | Назначение |
|---|---|---|
| `/inspire_hand/ctrl/{left,right}_hand` | `sensor_msgs/JointState` | в, цель `position` 0…1 |
| `/inspire_hand/state/{left,right}_hand` | `sensor_msgs/JointState` | из, 20 Гц; `velocity` — доля макс. скорости, `effort` — доля предела силы |
| `/inspire_hand/set_angle_flexible/{l,r}_hand` | сервис | то же, что `ctrl` |
| `/inspire_hand/set_speed/{l,r}_hand` | сервис | скорость пальцев: 1.0 = полный ход за 0.8 с (по умолч.), 0.5 = за 1.6 с |
| `/inspire_hand/set_force/{l,r}_hand` | сервис | предел силы: 1.0 ≈ 1000 г (по умолчанию) |
| `/inspire_hand/set_clear_error/{l,r}_hand` | сервис | всегда успешен: ошибок кисти в симуляторе нет |

У остальных узлов — стандартные сервисы параметров ROS 2 (`get_parameters` и т.п.).

## 5. Камеры и сенсоры

Две RGB-D камеры: `cam_head` и `cam_torso`, 640×360, FOV по горизонтали 86°, кадры ~5 Гц (раз в 3 шага физики). Системы координат оптические (z вперёд): `camera_head_link`, `camera_body_front_link`; внутренние параметры — в `camera_info`, положение относительно `pelvis` — в `/tf`. В режиме `--cams head` топиков `cam_torso` нет — проверяйте наличие. Головная камера видит штативы в шкафу при повороте корпуса на 1.57 рад.

| Топик | Тип | Частота | Примечание |
|---|---|---|---|
| `/cam_{head,torso}/color/image_raw` | `sensor_msgs/Image`, `rgb8` | ~5 Гц | |
| `/cam_{head,torso}/depth/image_raw` | `sensor_msgs/Image`, `16UC1` | ~5 Гц | миллиметры, выровнена по цветной; 0 = нет данных (< 0.15 м или > 6 м) |
| `/cam_*/{color,depth}/camera_info` | `sensor_msgs/CameraInfo` | ~5 Гц | фокус, центр |
| `/cam_*/points` | облако точек | ~5 Гц | |
| `/arm_6dof_{left,right}` | `geometry_msgs/WrenchStamped` | 20 Гц | внешняя нагрузка на кисть в рамке `wrist_roll_{l,r}_link`, вес кисти вычтен; расчётная величина — порядок силы/момента как на роботе, точные значения отличаются |
| `/clock` | `rosgraph_msgs/Clock` | 20 Гц | ⚠️ время симуляции |

## 6. Топики задачи

| Топик | Тип | Напр. | Примечание |
|---|---|---|---|
| `/sim/task` | `std_msgs/String`, JSON, latched | из | задача и правило; читать при старте |
| `/sim/objects/names` | `std_msgs/String`, JSON, latched | из | объекты и категории, без координат |
| `/sim/task/done` | `std_msgs/Empty` | в | сигнал завершения раскладки; на проверке по нему останавливается прогон |
| `/sim/task/check` → `/sim/task/result` | `Int32` → `String`, JSON | в → из | самопроверка; отладка, на проверке отключён |
| `/sim/objects/randomize` | `std_msgs/Int32` | в | новая раскладка по сидy; отладка |
| `/sim/objects/set` | `std_msgs/String`, JSON | в | `{"имя": [x, y, yaw]}`, x/y в метрах от таза; отладка |

Latched = durability `TRANSIENT_LOCAL`: подписчик с той же QoS получает последнее сообщение сразу. Форматы JSON — в [INTERFACES.md](INTERFACES.md).

## 7. Быстрые примеры

```bash
# Голова влево (head_yaw, мотор 3) на 0.5 рад со скоростью 0.5 рад/с
bash hackathon/tools/ros.sh "ros2 topic pub -t 3 /head/cmd_pos bodyctrl_msgs/msg/CmdSetMotorPosition \
  '{cmds: [{name: 3, pos: 0.5, spd: 0.5, cur: 1.0}]}'"

# Сжать правую кисть (0.2 ≈ почти кулак, большой палец 0.5)
bash hackathon/tools/ros.sh "ros2 topic pub -t 3 /inspire_hand/ctrl/right_hand sensor_msgs/msg/JointState \
  \"{name: ['1','2','3','4','5','6'], position: [0.2, 0.2, 0.2, 0.2, 0.5, 0.2]}\""

# Посмотреть задачу, нагрузку на запястье, калибровку камеры, TF камеры
bash hackathon/tools/ros.sh "ros2 topic echo --once /sim/task"
bash hackathon/tools/ros.sh ros2 topic echo --once /arm_6dof_right
bash hackathon/tools/ros.sh ros2 topic echo --once /cam_head/color/camera_info
bash hackathon/tools/ros.sh ros2 run tf2_ros tf2_echo pelvis camera_head_link

# Сигнал завершения раскладки
bash hackathon/tools/ros.sh "ros2 topic pub --once /sim/task/done std_msgs/msg/Empty '{}'"
```

## 8. Баллы и сдача

Каждый объект/пробирка весят 10 баллов. Проверяются `sort2` и `sort3` на пуле команды, дополнительная `sort2` на пуле 6 (по желанию) и все 4 варианта пробирок; непрошенную задачу можно пропустить, сразу опубликовав `/sim/task/done` — 0 баллов. Баллы за пробирки и пул 6 засчитываются, только если суммарный итог сортировок на своём пуле положителен. Итоги складываются по всем раскладкам.

| Итог по объекту сортировки / пробирке | Баллы |
|---|---|
| в сортировочном ящике своей категории / стоит в правильном штативе в шкафу | +10 |
| в ящике чужой категории / стоит в чужом штативе | −10 |
| взят и оставлен вне ящиков / взята и оставлена не в штативе: на столе, в шкафу, лежит или наклонена в гнезде | −10 |
| упал на пол / упала на пол | −10 |
| не тронут / не тронута | 0 |

Максимум на раскладке: `sort2` 60, `sort2` пул 6 ещё 60, `sort3` 90, `easy` 40, `standard` 90, `color` 60, `lying` 60. Лимит времени симуляции на раскладку: 45 с на объект сортировки, 60 с на пробирку (`sort2` 270, `sort3` 405, `easy` 240, `standard` 540, `color`/`lying` 360). Без `/sim/task/done` временем решения считается весь лимит. При равных баллах выше то решение, которое быстрее по времени симуляции → быстрее по реальному времени → меньше нагружает компьютер (CPU, RAM, VRAM) → проще и компактнее по коду. Совпадающий код (кроме шаблона `hello_world` и общедоступных библиотек) считается списанным — такие решения аннулируются.

**Формат сдачи** — репозиторий `nssr-sol-team-NNN`, ветка `main`: `src/` (пакеты ROS 2, colcon), `apt.txt`, `requirements.txt`, `setup.sh`, `run.sh`, `README.md` (обязательно: как устроено решение по каждой задаче, модели, запуск) + скринкасты по одной на каждую решаемую задачу/вариант (окно симулятора от старта до `/sim/task/done` + терминал со строкой `layout seed`; mp4 ≤ 2 ГБ, в Releases, не в git). Один `run.sh` на все задачи: решение само узнаёт задачу из `/sim/task`, само находит объекты камерами, в конце публикует `/sim/task/done`. Связь с симулятором только через ROS 2 (`ROS_DOMAIN_ID` и DDS уже заданы в контейнере). Интернет только на этапе установки: веса моделей качайте в `setup.sh` (файлы > 100 МБ GitHub не примет). Проверить формат: `bash hackathon/tools/solution.sh ~/nssr-sol-team-NNN`. В дедлайн репозиторий закрывается на чтение, проверяется последний коммит `main` до дедлайна.

## 9. Подводные камни и производительность

1. **Время симуляции.** Симулятор медленнее реального (~0.45× на ноутбуке с RTX 5080); метки камер и `/joint_states` идут по `/clock`. Узлы запускайте с `use_sim_time:=true`, иначе таймеры и ожидания вашего кода «убегут» в реальном времени.
2. **Ноги.** `/leg/*` есть для совместимости, но заморожены; двигается только корпус (мотор 31).
3. **Камеры.** В `--cams head` торсовой камеры нет; наличие топиков нужно проверять.
4. **Лимит 0.8 рад/с** действует и на итоговой проверке — решения «в обход» не пройдут.
5. **Недолёт ПД-приводов** до 15 % — позиционируйтесь замкнутым контуром по `/joint_states`.

Тормоза в основном от CPU: каждый кадр камер — подготовка сцены, чтение, отправка в ROS (десятки мс); физика ~2 мс/шаг. Помогает: ноутбук от сети + профиль «Производительность»; `--cams head` (~25 %); `HACK_TORSO_DEPTH=0` (~5 %); `HACK_VIEWPORT_SCALE=0.5` (~12 %); `--headless` + RViz2 (20–35 %). Рендер чаще (`HACK_RENDER_INTERVAL=1`) почти не добавляет кадров, а замедляет в 2–3 раза; физику на GPU переносить не нужно (`HACK_DEVICE`) — для одного робота CPU быстрее.
